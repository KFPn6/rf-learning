## 週に一回、見ること

日付範囲を過去7日にして、次の三つだけを見ます。一週の数字で目標の成否は決めません。月間のページビュー（PV）と照らすときの目安は、月 100 PV なら週およそ 25 PV、月 500 PV なら週およそ 125 PV です。週はばらつきます。

1. ページビュー（PV）
   ページが表示された回数です。目標の判定に使うのは、この月間合計です。
2. ユニーク訪問者
   人の数に近い参考値です。目標値は置きません。PV だけが増えて、ユニークが極端に少ないときは、同じ人が再読み込みしている可能性を疑います。開発中の確認も PV に入ることがあります。目標のために再読み込みを重ねないでください。
3. ページ別の上位
   どのページが読まれているかです。パスには `/rf-learning/` が付きます。入口として見てよいのは次です。
   - `/rf-learning/`
   - `/rf-learning/industry/`
   - `/rf-learning/learn/beginner/`
   - `/rf-learning/glossary/`

業界のページが読まれているか、入門で止まっているか、用語集だけが開かれているか、を週のメモに残すと、次に直す段落が決まります。数値をこのリポジトリへコミットする必要はありません。ダッシュボードが原本です。

JavaScript を切っている閲覧は、ビーコン方式では数え漏れます。サイトの本文はスクリプトなしでも読めます。

## 画面ごとの読み方

### Cloudflare Web Analytics（接続済み）

無料のアカウントで使えます。サイトの DNS を Cloudflare に移す必要はありません。

- Page views を、この文書の PV として読む
- Visits を、ユニーク訪問者に近い参考値として読む。表示名が Visitors でも、同じ欄の参考値として扱う
- Top pages（または Pages）を、ページ別の上位として読む
- 右上の期間を Last 7 days にする。月次の判定は、暦月か「過去30日」のどちらかに揃える。月の途中で範囲を変えて比べない

### Plausible

クラウド版は有料です。MVP では契約を要求しません。すでに契約があるか、自己ホストの無料版を動かしているときだけ使います。

- Unique visitors が参考値
- Total pageviews（または Pageviews）が PV
- Top pages がページ別の上位
- 期間は Last 7 days、月次は Month か Custom で暦月

### GA4（代替）

無料で使えますが、Cookie と Google への送信を伴います。プライバシーを優先するなら Cloudflare を先に検討します。

- 表示回数（Views）を PV とする
- ユーザー（Users）をユニークの参考値とする
- レポートの「エンゲージメント」→「ページとスクリーン」がページ別の上位
- 期間を過去7日、月次判定は暦月に揃える

## 暫定目標

市場調査に基づく需要予測ではありません。公開した直後の学習サイトについて、「届いたか」を判断できる大きさとして置いた置き値です。実績が貯まったら、この表の数字を先に書き換えて見直します。古い数字のまま、次節の作業には進みません。

| 時点 | 月間 PV | 月間の問い合わせ | 位置づけ |
| --- | --- | --- | --- |
| 公開後1ヶ月目 | 100 | 数えない | 暫定。途中経過の確認。これだけではポストゴールに進まない |
| 公開後3ヶ月目 | 500 | 数えない | 暫定。トラフィック目標の本線。この PV を超えた月でゲートが開く |

PV は、Cloudflare Web Analytics の Page views です。ゲートが開くまでは問い合わせフォームを置かないので、件数は数えません。ダッシュボードに数字が出る前の期間は、未達に数えません。`/contact/` の表示回数を問い合わせに代用しません。

フォームを接続したあとの暫定目安は、接続した月を 1ヶ月目として、1ヶ月目 1件、3ヶ月目 3件です。これは運営の置き値であり、英語版、モバイルの追加改善、フォーム設置の着手条件には使いません。着手条件は月間 PV が 500 以上であることです。

ユニーク訪問者には目標値を置きません。週次の読み方だけで使います。

## ゲート: 目標を超えるまで着手しない

英語版、モバイル表示の追加の磨き込み、Google フォーム（問い合わせフォーム）の設置は、同じポストゴールの作業です。トラフィックの暫定目標を上回ってから着手します。上回る前には着手しません。

判定に使うのは月間 PV だけです。

- ゲートが開く条件は、ビーコン開始後のいずれかの暦月で、月間 PV が 500 以上であること
- 1ヶ月目の 100 PV は途中経過です。100 を超えても、500 を超える月があるまではゲートは開きません
- 問い合わせの件数は、フォーム接続後の運営目安です。フォーム設置、英語版、モバイル追加改善の着手条件には使いません
- 500 未満の月しかないあいだは、英語の原稿も、狭い画面向けの見た目の作り込みも、Google フォームも始めません。`contact_form_embed_url` は空のままです

ゲートが開いたあとに着手してよいもの:

- 英語版（パスの設計や翻訳を含む。MVP では作らない）
- モバイルの追加改善。たとえば画面幅ごとの段組の作り直し、表のカード化、メニューの動きの追加など。読める状態からの上乗せです
- Google フォームの作成と、問い合わせページへの接続。埋め込み URL を `_config.yml` の `contact_form_embed_url` に入れる。`https://docs.google.com/forms/` で始まる URL だけが表示される。それまでは問い合わせページはプレースホルダのままにする

ゲートの前でも直してよいもの:

- 画面からはみ出す、押せない、読めない、といった不具合
- 事実の誤り、リンク切れ
- 計測トークンの接続
- 日本語の本文の追記と修正

目標値そのものを変えるときは、この表を先に更新します。更新前の数字を、頭の中だけで引き上げて着手しないでください。

## ゲートの外: MVP で満たすこと

スマートフォンで読めることは、目標達成を待たずに公開時点で満たします。追加の磨き込みとは別です。

- 幅 360px 相当でも、本文が画面の外にはみ出さない
- メニューから全ページへ到達できる
- 表は横にスクロールして最後の列まで読める
- 本文の文字サイズはおよそ 16px 以上
- リンクとボタンは、指で押せる高さを持つ

これは「モバイル対応を後回しにする」という意味ではありません。読めるレスポンシブ CSS は MVP の一部です。ゲートの対象は、その先の見た目の磨き込み、英語版、Google フォームの設置です。問い合わせページをプレースホルダのまま公開することも、MVP の一部です。

## 公開後に計測をつなぐ

接続は 2026-10-11（JST）に済ませました。以下は、そのときに踏んだ手順です。トークンを差し替えるときも同じです。

サイトが `https://kfpn6.github.io/rf-learning/` で開いてから行います。トークンを貼る前に本番 URL を決めておくと、ダッシュボードのホスト名と一致します。

貼ってよいのは、ビーコン用の公開トークンだけです。Cloudflare のアカウント API トークンや Global API Key は、リポジトリに置いてはいけません。ビーコンの token は、もともと HTML に出る公開の識別子です。

### Cloudflare Web Analytics（まずこちら）

1. Cloudflare の無料アカウントでダッシュボードを開く
2. Web Analytics を開き、サイトを追加する
3. ホスト名に `kfpn6.github.io` を入れる。DNS の移管（ネームサーバーの変更）は選ばない。JavaScript スニペットで計測する、を選ぶ
4. 表示されたスニペットから、`token` の値だけをコピーする
5. `_config.yml` を次のとおりにする。他の文章は書き換えなくてよい

```yaml
analytics:
  provider: "cloudflare"
  cloudflare_token: "コピーしたトークン"
  plausible_domain: ""
  plausible_src: "https://plausible.io/js/script.js"
  ga4_id: ""
```

6. `main` へ push する
7. 本番のページを開き、HTML に `static.cloudflareinsights.com/beacon.min.js` が含まれることを確認する
8. しばらくしてダッシュボードに Page views が出ることを確認する。出始めの日が 1ヶ月目の起点です

トークンが空、または引用符や空白を含む場合、サイトはビーコンを出しません。`provider` の綴りは `cloudflare` だけです。

### Plausible を使う場合

クラウド版は有料なので、MVP の必須手順ではありません。使うときだけ `provider` を `plausible` にし、`plausible_domain` にダッシュボードへ登録したドメイン（このサイトなら `kfpn6.github.io`）を入れます。

自己ホストしている場合は、`plausible_src` をそのサーバーの `https://…/js/script.js` に変えます。`https://` で始まらない URL は、サイト側で無視します。

### GA4 を使う場合

1. Google アナリティクスで GA4 プロパティとウェブストリームを作る。URL は `https://kfpn6.github.io/rf-learning/`
2. 測定 ID（`G-` で始まるもの）をコピーする
3. `provider` を `ga4`、`ga4_id` をその ID にする
4. push したあと、レポートに表示回数が出ることを確認する

三つの provider を同時には出しません。`provider` に書いた一つだけが有効です。

## 問い合わせフォーム（ゲートのあと）

月間 PV が 500 以上の月が出るまで、フォームは作りません。問い合わせページはプレースホルダのままにします。

ゲートが開いたあとだけ、次を行います。

1. Google フォームを作る
2. 埋め込み URL を `_config.yml` の `contact_form_embed_url` に入れる。`https://docs.google.com/forms/` で始まる URL だけが表示される
3. フォームの回答一覧を、暦月で数える。接続した月を 1ヶ月目とし、暫定目安は 1ヶ月目 1件、3ヶ月目 3件
4. 件数のメモをリポジトリに残す必要はない
